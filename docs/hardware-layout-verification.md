# Circuit layout and viewport correction

Baseline: `9e5785b`, **59 components, 165 exact connections**. The authoritative manifest, firmware, simulation reducer, AI client and research data are unchanged.

The regression had two causes: shelf packing put controllers beside the sensor row and power at the end of a tall sparse canvas; the initial camera then fitted both dimensions of that entire canvas. Existing checks asserted that everything fit, even when the resulting labels were unreadable. Fullscreen also invoked that same fit operation instead of restoring the user's camera.

The circuit now has two levels of detail using the same authoritative graph:

- **System Overview** lays out every component once in three explicit rows: PM/environmental monitoring; controllers/communication/drivers/safety; extraction/misting/power. The default camera fits width at a readable scale and permits vertical pan. Relationship groups partition the original connections; selecting a relationship lists its actual pin connections. Selecting hardware opens its detailed subsystem. Air and water links come from the original mechanical connections.
- **Detailed Wiring** retains individual physical anchors and the obstacle-aware orthogonal router. Fit Subsystem never automatically falls below 85%, giving the 12px carrier pin labels at least 10.2 screen pixels. Larger assemblies use pan instead of shrinking. Actual Size is 100%. The detailed layout also uses explicit architecture rows, with communication interfaces beside controllers and power alongside the physical systems.

**Fit Overview** explicitly requests a reduced full-architecture view. **Reset View** restores the readable default. Each detailed subsystem retains its camera between mode/tab changes; simulation ticks do not reposition hardware or alter zoom. Fullscreen preserves selected pins/wires and restores the previous zoom and pan when closed with its button or Escape. The mini-map is available on demand so it does not cover hardware labels by default. Exports name the visible overview and pin-wiring diagrams distinctly; the complete original wiring CSV remains available.

Validation adds assertions for width utilization, rendered pin size, three desktop sizes (1366×768, 1440×900, 1920×1080), architecture rows, group separation, exact inventory/relationship preservation, actual-size/overview/reset actions, all subsystem views, search, wire tracing, category filters, pointer zoom, drag pan, mini-map, fullscreen camera restoration, camera stability during live simulation, and mode persistence. Screenshots and the JSON browser report are written under ignored `.hardware-qa/layout-*`.

Commands: `npm.cmd ci --offline --cache .tooling/npm-cache`, `npm.cmd test`, `npm.cmd run build`, `node tests/browser/hardware-layout.cjs`, `node tests/browser/hardware-smoke.cjs`. The existing `hardware-wiring.cjs` command forwards to the new readability regression, replacing the obsolete fit-everything expectations. Hardware Python checks exercise the unchanged host/protocol; real AI calls and the existing nine website routes are covered by the full browser regression. No new hardware, firmware execution or physical verification is claimed.

Executed results: **110 frontend tests passed**, **16 hardware Python tests passed**, dependency installation and production build passed. The complete browser regression passed all **26 scenarios**, real AI, Python host control/fail-off, code/configuration/ZIP workflows, mobile and nine website routes without uncaught browser errors. Desktop captures verify roughly **98% default overview width utilization** at all three specified resolutions; detailed pin text is checked at a minimum 10px screen size. Explicit fullscreen Fit Overview now shows the complete compact architecture, with its viewport centered instead of leaving a small cluster against the left edge.
